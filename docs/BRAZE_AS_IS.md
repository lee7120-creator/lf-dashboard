# LF Mall CRM 발송 환경 AS-IS

**작성 목적** Braze 도입 검토를 위한 현행(AS-IS) 발송 환경 공유
**기준 시점** 2026년 9월
**작성 범위** LF Mall CRM 발송(자동화 트리거 메시지 + 대량 캠페인 발송)과 그 성과 측정 체계
**문서 성격** 현행 운영 실태를 있는 그대로 정리한 자료입니다. 개선안(TO-BE)은 포함하지 않았고 현행 체계의 제약만 11장에 따로 모았습니다.

---

## 0. 이 문서를 읽는 법

- 수치는 별도 표기가 없으면 **2026년 9월 기준 운영 실적 백업**에서 집계한 값입니다.
- 「갈래 A」는 고객 행동에 반응해 자동으로 나가는 트리거 메시지, 「갈래 B」는 영업·마케팅 요청으로 나가는 대량 캠페인입니다. **두 갈래가 별개 체계로 운영되고 있다는 점이 현행 환경의 핵심**이라, 문서 전체를 이 구분으로 나눠 놓았습니다.
- 4장과 부록 A의 메시지 코드(LL01, O001, K0400 등)는 현행 운영 코드 그대로입니다.

## 2. 발송 체계 개요 — 두 갈래로 갈려 있습니다

```
                    ┌──────────────────────────────────────┐
                    │  갈래 A — 자동화 트리거 메시지 (27건)  │
  고객 행동 이벤트 → │  가입·구매·배송완료·미방문·장바구니 등  │ → SMS / 알림톡 / 앱PUSH
  (가입, 구매, 이탈) │  코드 체계: LL·O·P·K·EV             │
                    └──────────────────────────────────────┘

                    ┌──────────────────────────────────────┐
                    │  갈래 B — 대량 캠페인 발송              │
  영업·마케팅 요청 → │  기획 구글시트 → 발송 → 실적 엑셀      │ → 앱PUSH 중심
  (기획전, 세일)     │  코드 체계: AP·PB (+ 일부 EV)         │
                    └──────────────────────────────────────┘
                                    ↓
                    ┌──────────────────────────────────────┐
                    │  측정 — 자체 제작 대시보드 2종          │
                    │  발송성과 대시보드 / 주간보고 대시보드    │
                    │  (파일 업로드 기반, 발송 플랫폼 미연동)   │
                    └──────────────────────────────────────┘
```

**두 갈래는 코드 체계·기획 방식·측정 경로가 모두 다릅니다.** 갈래 A는 코드가 고정된 상설 시나리오이고 갈래 B는 주차 단위로 새로 기획하는 일회성 캠페인입니다. 같은 고객이 양쪽에서 메시지를 받아도 현재는 한 화면에서 합산되지 않습니다.

## 3. 채널 현황

### 3.1 운영 채널

| 채널 | 자동화(갈래 A) | 대량 캠페인(갈래 B) | 비고 |
|---|---|---|---|
| **SMS / LMS** | 15건 | 일부 | 자동화의 주력 채널 |
| **앱 PUSH** | 9건 | **주력** | 카탈로그 연동 실시간 트리거 9종이 전부 이 채널 |
| **카카오 알림톡** | 3건 | — | 정보성(전환 완료, LIVE 방송 알림) 위주 |
| **카카오 플러스친구** | 0건 | — | 채널 정의는 있으나 자동화 시나리오 미편성 |
| **이메일** | 0건 | — | 채널 정의는 있으나 자동화 시나리오 미편성 |
| **인앱 메시지** | 0건 | — | 미운영 |

> 플러스친구·이메일·인앱은 채널 구분으로는 정의되어 있으나 **현재 자동화 시나리오에는 한 건도 편성되어 있지 않습니다.**

### 3.2 앱 PUSH 수신 모수

- 수신동의 모수를 **분모가 다른 두 원천**으로 관리합니다.
  - **앱 보유 회원 기준** 동의율 — 앱을 설치한 회원 중 수신동의 비율
  - **신규회원 전체 기준** 동의율 — 앱 설치 여부와 무관한 그날 신규회원 전체 중 수신동의 비율
- 두 값의 차이가 곧 「앱을 설치하지 않아 PUSH를 받을 수 없는 몫」입니다.
- **PUSH 수신동의 순증이 월 –300명 수준으로 감소 추세**입니다(신규추가 − 기존이탈).
- 앱 설치 실적은 별도 앱 대시보드 export로 2026년 3월부터 적재를 시작했습니다. 그 이전 데이터가 없어 **전년 동기 비교가 불가능**합니다.

## 5. 갈래 B — 대량 캠페인 발송 운영

### 5.1 발송 구좌 체계

- 하루에 정해진 수의 **발송 구좌**를 두고 영업 사업부·마케팅·편성·브랜드컨텐츠가 요청한 캠페인을 배정하는 방식입니다.
- **2026-08-01 정책 변경**
  - 영업 세일즈 구좌: **10개 → 5개**로 축소
  - **16시 구좌를 「컨틴(컨틴전시)」 구좌로 신설**
  - 변경 이전에는 구좌가 남으면 타겟팅 없이 남은 모수로 내보내는 「남은발송」이 **전체의 20% 가까이** 발생했습니다.
- 발송량 축소 이후, 잔여모수 추가·컨틴 배정으로 발송량을 다시 조정하는 단계에 있습니다.

### 5.2 캠페인 식별 체계 — AF코드

- 형식: `AP` 또는 `PB` 접두어 + 숫자 (예: `AP101`, `PB03`). 접두어와 숫자 사이에 영문이 끼는 경우도 있습니다(`APZ04`, `APZ09`). 일부 `EV**` 코드도 실적에 포함됩니다.
- **AF코드는 매주 재사용됩니다.** 실적 백업 기준으로:
  - AF코드 1개당 평균 **36개 날짜**에 사용
  - 최다 사용 코드(AP80)는 **84개 날짜**에 사용
  - 전체 코드의 **89%가 2개 이상의 날짜**에 사용
- 따라서 **AF코드 단독으로는 캠페인 1건을 식별할 수 없고** `(발송일자, AF코드)` 조합이 실질 식별자입니다. 동일 일자에 같은 코드가 두 번 나오는 경우(원발송 + 잔여모수 추가분)도 있습니다.

### 5.3 발송 분류 축

현행 실적 데이터는 캠페인을 아래 축으로 가릅니다.

| 축 | 값 | 비고 |
|---|---|---|
| **발송유형(stype)** | 우수발송 1~8 · 컨틴 · 시그니처 · L:ABLE · 남은발송 등 | 수기 입력이라 표기 흔들림 존재(「컨틴전시 A/B」↔「컨틴」, 「시그니처」↔「시그니쳐」) |
| **BPU** | 1BPU ~ 4BPU (영업 사업부) / 마케팅 / 편성 / 브랜드컨텐츠 | 발송 요청 주체 |
| **우선순위** | 1 ~ N | 같은 시간대에 몇 번째로 나갔는지 (0과 1은 동일 의미로 통합) |
| **발송 시간대** | HHMM | 수기 입력. `2400`(자정 표기), `8000`(→800 오타) 등 비정형 값 혼입 |
| **카테고리** | 야간푸시 외 | 캠페인 성격 구분 |
| **속성** | 마케팅 외 | |
| **타겟 구분** | 신규 · 휴면 · 전체 등 | 세그먼트 구분 |
| **브랜드** | 브랜드명 | **수기 입력이라 캠페인명·행사명이 섞여 들어옵니다** (「위켄드세일 추가 적립」, 「L+DAY 쇼핑핫타임 1차」 등) |
| **담당자** | 담당자명 | |
| **기획전** | 기획전명 | |

### 5.4 우선순위와 발송량의 관계 (현행 실태)

- 「남은발송」은 우선순위별로 몰려 있습니다. 2026년 실적 기준 **1순위 발송의 0.9%만 남은발송**인 반면 **2·3·4순위는 50~56%**가 남은발송입니다.
- 구좌 축소 이후 한 번에 내보내는 모수가 늘었습니다. 1~3순위 캠페인당 발송이 **15~17만 → 18~20만 건**으로 증가했습니다.

## 6. 타겟팅·세그먼트 현황

### 6.1 갈래 A (자동화)

- 트리거 조건 자체가 세그먼트 역할을 합니다: 가입 경과일, 구매 횟수(1회/2회/3회), 배송 완료, 미방문 일수, 장바구니·찜·조회 이력, 회원 등급(BK/SV/VIP), 쿠폰 보유·미사용 여부.
- 제외 조건은 캠페인별 개별 설정입니다(예: O001 「30일 내 구매자 제외」).
- **행동 기반 실시간 세그먼트는 상품 카탈로그 연동 9종에 한정**됩니다. 나머지는 경과일 기반 스케줄 발송입니다.

### 6.2 갈래 B (대량 캠페인)

- 「타겟 구분」 칸에 신규·휴면·전체 등으로 표기됩니다.
- 타겟팅 없이 남은 모수로 내보내는 「남은발송」이 정책 변경 이전 20% 수준이었고 현재도 2~4순위에서는 50% 이상입니다.
- **잔여모수 추가 여부**가 기획 시트에 별도 관리 항목으로 존재합니다. 동일 캠페인을 원발송 후 남은 모수에 추가 발송하는 운영입니다.

### 6.3 조직·상품 축

- 성과 분석용으로 **영업조직 > 카테고리 > 브랜드 > 상품** 4단 계층이 정의되어 있습니다.
- 다만 현행 데이터 export에서 **브랜드·상품 칸이 비어 옵니다.** 실질적으로 조직 > 카테고리 2단만 사용 가능하고 브랜드·상품 단위 분석은 별도 결제 원장을 따로 받아 처리합니다.
- LFMS 포함여부(Y/N)라는 모집단 구분 축이 하나 더 있어 같은 기간·같은 조직이라도 이 값에 따라 총계가 달라집니다.

## 7. 문구·크리에이티브 운영

### 7.1 기획·작성

- 대량 캠페인 문구는 **구글 스프레드시트에 주차별 시트로 수기 작성**합니다.
  - 시트명 형식: `1월 1주차(1229~14)`
  - 시트 항목: 일자 · AF코드 · 제목 · 내용 · 문구 변경 여부 · 잔여모수 추가 여부
- 「문구 변경 여부」는 원안 대비 문구를 다듬었는지 표시하는 칸이고 빈칸은 「검토했으나 그대로 집행」을 뜻해 대조군으로 사용합니다.
- 자동화 메시지 문구는 시나리오에 고정 등록되어 있고 `#{고객명}`, `#{상품명}`, `{DC_RATE}`, `#{검색어}` 등의 치환 변수를 사용합니다.

### 7.2 문구 소구 속성

성과 분석을 위해 문구를 자동 분류하는 15개 소구 축을 운영합니다.

| 구분 | 소구 속성 |
|---|---|
| 혜택형 | 할인율소구 · 가격소구 · 쿠폰적립 · 사은품증정 |
| 긴급·희소 | 마감임박 · 한정희소 |
| 상품·추천 | 신상컬렉션 · 베스트인기 · 추천큐레이션 · 시즌환절기 |
| 행동·참여 | 행동리타겟(장바구니·찜·최근본) · 이벤트응모 · 라이브방송 |
| 형식 | 개인화 · 알림안내 (+ 질문형 · 이모지 사용 여부) |

이 분류는 **발송 후 성과 분석 단계에서 문구 텍스트를 읽어 자동 태깅**하는 것이며 발송 시점에 시스템이 관리하는 속성은 아닙니다.

### 7.3 A/B 테스트

- 플랫폼 차원의 A/B 테스트 기능은 사용하고 있지 않습니다.
- 대신 「문구 변경 여부」·「잔여모수 추가 여부」 플래그를 사후 대조군으로 삼아 층화 보정과 Welch 검정으로 효과를 사후 검증하는 방식입니다.

## 9. 측정·리포팅 현황

### 9.1 리포팅 체계

- **발송성과 대시보드** — 캠페인 단위 성과, 문구 소구 분석, 시간대·카테고리, 발송량·피로도, 개선 효과 검증 등 10개 그룹 28개 화면
- **주간보고 대시보드** — 첫구매 퍼널, 채널별 실적, 조직·카테고리별 실적, 앱푸시 동의 현황 등 8개 페이지
- 두 대시보드 모두 **파일 업로드 기반**입니다. 담당자가 export한 파일을 올리면 집계·저장합니다.

### 9.2 핵심 지표 정의

| 지표 | 정의 |
|---|---|
| CTR (유입전환율) | UV ÷ 발송 |
| 주문전환율 (CR) | 주문 ÷ UV |
| RPS | 거래액 ÷ 발송 |
| 객단가 (AOV) | 거래액 ÷ 주문 |
| 인당 발송 건수 | 고객 1명이 하루에 받은 평균 메시지 수 (발송 강도·피로도 지표) |
| 유입 대비 구매전환율 | 구매 고객수 ÷ 유니크 유입 |
| 기여율 | 발송 추적 거래액 ÷ 기획전 유입 거래액 |

> **CTR의 분모가 원천에 따라 다릅니다.** CRM 실적 엑셀은 `UV ÷ 발송`(발송 1건당), 전사 MTD 파일은 `유니크유입 ÷ 유니크발송고객수`(고객 1명당)입니다. 현재는 화면에서 이 차이를 주석으로 안내하는 방식으로 운용하고 있습니다.

### 9.3 첫구매 퍼널

```
비회원트래픽 → 가입율 → 가입자수 → 당일가입CR → 첫구매 고객수 → 첫구매 객단가 → 첫구매 거래액
```

- 마지막 「첫구매 고객수」는 당일 가입자뿐 아니라 **과거 가입자의 첫구매까지 포함**하므로 `가입자수 × 당일가입CR ≠ 첫구매 고객수`입니다. 퍼널 곱셈이 닫히지 않는 구조입니다.
- 채널 축(직접·광고·EP·PUSH·제휴·브랜드광고·미디어커머스)과 조직 축(영업조직 > 카테고리)으로 각각 분해할 수 있으나, **두 축은 교차되지 않습니다.** 원천 데이터가 다르기 때문입니다.

### 9.4 발송 성과 귀속(attribution)

- 현행 귀속은 **발송 → 유입(UV) → 주문**을 실적 파일이 이미 연결해 준 상태로 받습니다. 귀속 윈도우·모델(라스트터치 여부 등)은 발송 플랫폼과 BI 쪽에서 정의되어 있고 CRM 측에서 설정을 조정하지 않습니다.
- 성과 대시보드가 집계하는 실적 파일은 **AF코드(AP·PB 계열) 기반 대량 캠페인**이 중심입니다. 자동화 트리거 메시지(LL·O·P·K 계열)는 이 실적 체계에 캠페인 단위로 들어오지 않아, **갈래 A의 캠페인별 CTR·전환 성과를 같은 화면에서 추적하지 못합니다.** 월 단위 스케줄 발송인 EV 계열(EV00·EV21·EV25)은 실적 백업의 일부 시트에 코드가 나타나므로, **실제 적재 범위는 업체 논의 전에 한 번 확인이 필요합니다.**

## 10. 현행 체계의 제약

Braze 도입 검토 시 참고하실 수 있도록, 현재 운영에서 확인되는 제약을 정리했습니다. 우선순위나 요구사항이 아니라 **사실 기술**입니다.

### 10.1 고객 접점 통합

1. **통합 고객 프로파일이 없습니다.** 갈래 A(자동화)와 갈래 B(대량 캠페인)가 별개로 운영되어 한 고객이 하루에 받은 메시지 총량을 캠페인 단위로 되짚을 수 없습니다. 전사 「인당 발송 건수」 집계치로만 간접 확인합니다.
2. **전사 빈도 제한(frequency capping)이 없습니다.** 중복 억제가 캠페인별 개별 규칙(30일 내 구매자 제외 등)으로만 걸려 있습니다.
3. **채널 간 폴백·우선순위 로직이 없습니다.** 예를 들어 PUSH 미수신 고객에게 SMS로 대체 발송하는 규칙이 시나리오에 없습니다.

### 10.2 시나리오 커버리지

4. 가입 직후 **0~2시간 골든타임 트리거 부재** (첫 접점이 D+1 SMS)
5. **주문서(결제창) 이탈 대응 부재**
6. 배송완료 ~ 구매 D+7 사이 **7일 공백**, 리뷰 유도 시나리오 부재
7. **3회 구매 → VIP 이관 자동화 부재**, 등급 넛지 부재
8. **일반 고객 Win-back 부재** (EV00의 조건이 「30일 이상 미방문 + 6개월 내 2회 이상 구매」로 한정되어 구매 1회 이하 고객은 이탈해도 복귀 메시지를 받지 않음)
9. **이메일·플러스친구·인앱이 자동화에 편성되어 있지 않음**
10. 「가입/미구매」·「재구매」·「VIP 이관」 3개 단계가 **SMS 단일 채널 의존**

### 10.3 데이터·운영

11. **발송 플랫폼 ↔ 분석 체계 간 직접 연동 부재.** 실적·문구·조직·앱·사이트 6개 원천을 모두 파일 export로 수령해 수동 업로드합니다.
12. **기획 문구가 구글 스프레드시트 수기 관리.** 발송 시스템과 문구 원장이 분리되어 있어 `(일자, AF코드)` 조인으로 사후 결합합니다.
13. **AF코드 재사용**으로 캠페인 단위 고유 식별자가 없습니다.
14. 실적 필드 다수가 **수기 입력**이라(시간대·브랜드·발송유형·속성) 파서 단계에서 보정이 필요하고 브랜드 특정률이 42%에 머뭅니다.
15. **자동화 메시지(갈래 A)의 캠페인별 성과가 대량 캠페인과 같은 체계로 집계되지 않습니다.** (EV 계열 일부 제외 — 9.4 참조)
16. **브랜드·상품 단위 축이 조직 export에서 비어 옵니다.** 별도 결제 원장을 받아 따로 처리합니다.
17. **앱 설치 데이터가 2026년 3월부터**라 전년 동기 비교가 불가능합니다.
18. **앱PUSH 수신동의 순증이 월 –300명**으로, 주력 채널의 도달 모수가 줄고 있습니다.

## 11. 업체 확인 요청 사항

Braze 도입 시 다음 항목이 현행 운영과 어떻게 매핑되는지 확인 부탁드립니다.

**데이터 연동**
1. 실적·문구·조직·앱·사이트 6개 원천 중 어디까지 Braze Currents / Cloud Data Ingestion으로 직접 수집 가능한지
2. 기존 AF코드 체계를 캠페인 식별자로 유지할 수 있는지, 아니면 신규 체계로 전환해야 하는지 (과거 실적과의 연속성 확보 방안)
3. 상품 카탈로그(가격·재고) 연동 방식과, 현행 실시간 PUSH 9종의 트리거 조건 이관 가능 범위

**시나리오**
4. 27건 자동화 시나리오의 이관 방식과 예상 소요 기간
5. 전사 빈도 제한(frequency capping)과 채널 폴백 설정 방법
6. 갈래 B(대량 캠페인) 구좌 운영을 Braze에서 어떻게 표현할 수 있는지 (우선순위·발송유형·BPU 축 유지 가능 여부)

**측정**
7. 귀속(attribution) 윈도우·모델 설정 범위와, 현행 실적 파일 지표(UV·VISIT·유입전환율·주문전환율·효율)와의 대응 관계
8. 자동화 메시지 캠페인별 성과를 일 단위로 집계·export 가능한지
9. 현행 자체 대시보드 2종에 데이터를 공급할 수 있는 export 경로

**운영·전환**
10. 기존 수신동의 데이터(앱 보유 기준 / 신규회원 전체 기준 두 벌) 이관 방식
11. 전환 기간 중 기존 발송 체계와의 병행 운영 가능 여부
12. 담당자 교육 범위와 문구 등록·승인 워크플로
